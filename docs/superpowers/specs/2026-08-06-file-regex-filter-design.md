# `--file` 正则包含/排除设计

## 背景

`--file` 当前支持逗号分隔的文件名、glob 和以 `^` 开头的排除项。固定目录和扩展名可以用 glob 处理，但无法表达“扩展名属于某集合且名称不包含某段文本”等条件。

## 目标

在不增加 CLI 选项、不改变现有 glob 行为的前提下，为 `--file` 增加正则包含和排除语法：

- `REG:<expr>`：包含匹配正则的归档条目。
- `^REG:<expr>`：排除匹配正则的归档条目。

正则使用 Go 标准库 `regexp` 语法，默认区分大小写。需要忽略大小写时由调用者在表达式中使用 `(?i)`。

## 解析与匹配

`NewFileChooser` 继续按逗号拆分表达式。每一项按以下顺序解析：

1. 去除首尾空白。
2. 识别可选的排除前缀 `^`。
3. 识别可选的正则前缀 `REG:`。
4. `REG:` 项编译为正则 chooser；其他项继续使用现有 glob chooser。

正则同时匹配：

- 规范化为 `/` 分隔符的完整归档路径。
- 该路径的 basename。

任一匹配即视为命中，与现有 glob chooser 保持一致。目录和普通文件使用同一规则。

## 组合语义

- 包含项和排除项可以混用。
- 排除项优先，命中排除后不能由包含项重新加入。
- 只有排除项时，隐式包含其他所有条目。
- 普通 glob、`REG:` 和 `^REG:` 可以出现在同一个逗号分隔表达式中。
- 保留现有逗号分隔规则；本次不处理正则表达式自身包含逗号的转义。

示例：

```powershell
eget dl --file "^REG:(?i)\.(map|cmd|md|txt|diz)$" owner/repo
eget dl --file "REG:(?i).*eng.*\.(hlf|lng)$,^REG:(?i)\.(map|cmd)$" owner/repo
```

## 错误处理

- `REG:` 或 `^REG:` 后为空时返回明确错误。
- 正则编译失败时返回包含原表达式上下文的错误。
- 不吞掉错误，也不回退为 glob。

## 实现范围

主体修改限制在 `internal/install/chooser.go`：复用现有 `Chooser` 接口，增加最小正则 chooser，并让现有过滤解析选择 glob 或正则实现。

测试修改限制在 `internal/install/chooser_test.go`，覆盖：

- 正则包含完整路径和 basename。
- 正则排除。
- 仅正则排除时隐式包含其他条目。
- glob 与正则混用。
- 非法和空正则报错。
